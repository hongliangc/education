# 上下五千年 · 第一期(三国垂直切片) — 设计 spec

> 状态：设计已确认，待转 writing-plans。
> 日期：2026-06-24　项目：魔法学习王国(MLK)　目标用户：3–10 岁儿童。
> 来源讨论：`todo/上下五千年.md`、`todo/上下五千年/人物卡片设计.md`。

## 1. 背景与目标

新增「上下五千年」历史板块。核心理念（来自 todo）：

> **先被人物和故事吸引，再通过收集与考验建立历史认知；并且分清"故事"与"史实"。**

第一期不做整个五千年，先做一个**三国垂直切片**作为可验证闭环：验证孩子是否愿意主动看第二、第三个故事、是否愿意为升级卡片继续学习。验证成功后再按朝代横向扩展。

学习闭环（来自人物卡片设计）：

> **遇见人物 → 听故事 → 完成考验 → 获得卡片 → 深入学习 → 升级卡片 → 组成历史名人堂。**

## 2. 范围

**做（第一期）**

- world 地图新增「上下五千年」🏯 板块节点 → `/history` 路由。
- 三国"时代页"：横向朝代条 + 6 故事卡 + 群英谱卡墙 + 历史向导精灵入口。
- 6 个三国故事，复用现有 StoryPlayer/StoryBook 引擎。
- **历史群英谱** 12 张人物卡：三档掌握等级（相识·灰 / 了解·彩 / 精通·金）、6 属性雷达、专长、可考证荣誉徽章、正史/演义/传说标记、卡背史册内容。
- 收集两道 gate：章末理解题 → 彩卡；人物多维考验 → 金卡。
- 套组（如「蜀汉群英」）集齐 → 称号 + 朝代拼图（写 `Achievement`）。
- 每故事末「演义 vs 史实」对照小卡（轻量可信度）。
- 历史向导精灵：`/api/fairy/chat` 按 `context=history` 切 system prompt，区分史书/演义/传说/有争议。
- 视觉方向「三国群英·锦卷」（见 §8）。

**不做（留二期）**

史家认证·动态典藏卡、人物关系动态图、专题动画、可缩放历史长河、真实历史地图/城市点亮寻宝、历史侦探推理、关键时刻分支选择、三国以外的朝代。

## 4. 数据模型

### 4.1 内容文件（纯数据，无 React / 无 `@/`）

- `content/storybooks/three-kingdoms.ts` — 一本 `StoryBook`（id `three-kingdoms`、kind `novel`、6 章）。
- `content/history/three-kingdoms-cards.ts` — 12 张人物卡（卡面/卡背全字段，见 §6）。
- `content/history/three-kingdoms-trials.ts` — 人物考验题库，每人物 5 维（识其人/知其事/懂其言/明其功/能辨析）若干题，考验时抽 3–4。
- `content/history/sets.ts` — 套组定义（如「蜀汉群英」= 刘备/关羽/张飞/诸葛亮/赵云）。

`content/storybooks/types.ts` 的 `Chapter` 增两个**可选**字段（向后兼容现有书）：

```ts
historyNote?: { romance: string; history: string }; // 演义这样写 / 史书可能这样
cardKeys?: string[]; // 该章读完点亮"相识"、章末题答对升"了解"的人物卡 key
```

### 4.2 Prisma 新表（镜像 `VideoUnlock` 的最小解锁表）

```prisma
model HistoryCardUnlock {
  id         String   @id @default(cuid())
  childId    String
  child      Child    @relation(fields: [childId], references: [id], onDelete: Cascade)
  cardKey    String   // three-kingdoms-cards.ts 内容常量，非外键
  tier       String   // UNDERSTOOD(了解·彩) | MASTERED(精通·金)
  unlockedAt DateTime @default(now())

  @@unique([childId, cardKey])
  @@index([childId])
}
```

- `Child` 增 `historyCardUnlocks HistoryCardUnlock[]`。
- 「相识·灰」**不落库**：由 `ReadingProgress`（该卡所属章节是否已读）推导。
- 卡片**不进**星星经济（不动 `RewardResource` / `StarLedger` / `RewardRedemption`）——与"答对/考验解锁、体现学习进度而非金币"一致。

## 5. 核心闭环：历史群英谱

三档掌握阶梯 + 两道 gate：

| 档位 | 卡面 | gate |
|---|---|---|
| 相识 · 灰卡 | 剪影 + 锁 | 人物在**已读章节**出现过（自动，ReadingProgress 推导） |
| 了解 · 彩卡 | 翻面解锁、阵营锦缎描边 | 读完该人物所属章节 + **章末 2–3 题答对** |
| 精通 · 金卡 | 鎏金描边 + 朱砂印 | 完成该人物**「人物考验」**（5 维抽 3–4 题）全过 |

- **低龄友好**：章末题与人物考验都允许重试、答错给提示；最终都能拿到卡，只是档位差别，不卡死。
- **升级动机**：彩卡 → 金卡 需要"深入学习"（看卡背史册 + 通过多维考验），解决"得卡即弃学"。
- **套组**：集齐套组（如「蜀汉群英」5 张全部到"了解"以上）→ 颁称号 + 点亮朝代拼图（写 `Achievement`）。人物关系图/地图路线等套组奖励属二期，第一期套组只发称号/拼图。
- 史家认证·动态典藏卡 = 第四档，二期。

## 6. 卡片信息模型

**正面**：画像（emoji 占位 → 后续插画）、姓名 + 字号、朝代、势力（蜀/魏/吴）、一句人物定位、掌握等级、**6 属性雷达图**、荣誉徽章。

**6 通用属性**（适配所有历史人物，非战力数值）：谋略 / 治理 / 军事 / 学识 / 品格 / 影响。每项用 **5 级评价文字**：`了解 → 出众 → 卓越 → 时代代表 → 千古影响`，并附一句**依据**（如"谋略·卓越｜依据：隆中对、联吴抗曹"）。卡上明示："网站据资料设计的**学习属性**，非权威结论"。再加 **1–2 专长**（诸葛亮：谋略、治理；关羽：武勇、统兵）。

**卡背（史册）**：人生时间线、主要事迹、代表作品 & 名句、典故、历史贡献、争议 / 不同评价、**正史 / 演义 / 传说**标记、相关人物与地点。

**荣誉徽章**：只用可考证项（武庙十哲 / 从祀、文庙四配 / 十二哲、凌烟阁、云台二十八将、教材入选…），**不显示"第 N 名"排名**。每枚点开解释：设立朝代 / 入选层级 / 入选原因 / 后世是否调整 / 资料来源。

**第一期 12 人物**（覆盖三阵营 + 蜀汉群英套组）：

- 蜀（5，套组）：刘备、关羽、张飞、诸葛亮、赵云
- 魏（3）：曹操、司马懿、张辽
- 吴（4）：孙权、周瑜、鲁肃、黄盖

**第一期 6 故事**：桃园三结义、三顾茅庐、草船借箭、赤壁之战、空城计、七擒孟获。卡片随其所属章节阅读/考验点亮。

## 7. 演义 vs 史实（轻量可信度）

- 每故事末「演义这样写 / 史书可能这样」对照小卡（来自 `chapter.historyNote`，各 1–2 句）。
- 历史向导精灵：`/api/fairy/chat` 传 `context=history` 时切到历史 system prompt，回答区分并标注 **史书记载 / 文学演绎 / 民间传说 / 目前有争议**。
- 卡背与典故带同款标注（如关羽青龙偃月刀 → 文学演绎；三顾茅庐 → 正史有载；草船借箭 → 演义艺术加工）。

## 8. 视觉与 UI 设计 —「三国群英·锦卷」

刻意避开 AI 默认三套路（奶油底+衬线、近黑+荧光、报纸栏），从"印绶 / 竹简 / 三分天下"题材长出辨识度，并与现有儿童 UI 套件一致（页面背景沿用 app 现有彩色天空，绢面只做卡片/卷轴表面，不做整页奶油底）。

**色彩令牌**

| 名 | hex | 用途 |
|---|---|---|
| 蜀绿 | `#2E8B6B` | 蜀阵营 / 板块主色 |
| 魏蓝 | `#2C4A7E` | 魏阵营 |
| 吴赤 | `#C2402F` | 吴阵营 |
| 朱砂 | `#C8352B` | **印章签名专用** |
| 鎏金 | `#C9A24B` | 金卡描边 / 荣誉徽章 |
| 绢面 | `#F3ECDA` | 卡片 / 卷轴表面（非整页背景） |
| 墨 | `#2B2622` | 主文字 |

**字体（3 角色）**

- 展示：`Noto_Serif_SC`（heavy），按现有 `next/font/google` 模式加 `--font-history`，仅用于回目标题、人物名、朝代等，克制使用，史册/碑刻感。
- 正文：沿用现有站酷快乐体 `--font-kid`（`ZCOOL_KuaiLe`）。
- 工具：小字楷/等宽，用于"依据 / 来源 / 正史·演义·传说"标签。

**布局**

- 朝代条 = **竹简卷轴横轴**：三国段"展开"高亮可点，其余"卷起"灰显「敬请期待」。
- 时代页 = 三阵营色分区；故事卡 = 连环画 / 章回 panel；群英谱 = 名人堂卡墙。
- 卡片 = 绢框人像 + 阵营色描边 + 六边形雷达 + 掌握等级印；点击翻面看史册背面；档位描边 素 → 阵营锦 → 鎏金。

**签名元素**：**朱砂盖章** —— 获得/升级卡片时一枚印章带"按压 + 墨迹晕染"盖在卡上，相识/了解/精通 印记逐级丰富。大胆只花在此一处，其余保持安静、复用现有套件。

**动效（克制）**：进三国页一次卷轴展开；得卡盖章；点卡翻面。尊重 `prefers-reduced-motion`。可复用 `globals.css` 既有动画，新增的盖章/翻面控制在最小集。

## 9. 内容产出

- 12 卡文案 + 考验题库由内容编写，属性"依据"与荣誉徽章须可考证、标来源。

## 10. API

- 复用 `GET/POST /api/reading/[childId]` 写章节阅读进度（顺序解锁、章末题通关）。
- 新增卡片解锁接口（鉴权 + 校验 child 归属，upsert `HistoryCardUnlock`，返回更新后状态与套组达成）：
  - `POST /api/history/cards`（body：`{ childId, cardKey, tier }`），未登录返回 401。
  - `GET /api/history/[childId]/heroes` 返回该孩子 12 张卡的 灰/彩/金 状态（彩/金读库，灰由阅读进度推导）。
- 第一期解锁判定信任客户端通关结果（与现有 session 模型一致）；服务端硬校验留待与 deferred-session-stars-trust 一并加固。
